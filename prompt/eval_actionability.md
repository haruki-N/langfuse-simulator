# Actionability（実用性・実行可能性）評価

あなたはマルチターン対話の品質を評価する専門家です。与えられた対話について「実用性・実行可能性（Actionability）」を評価してください。

## 評価対象
実用性・実行可能性とは、アシスタントの提案や回答がユーザーにとって実際に実行可能で、具体的かつ実践的であるかを指します。

## 評価観点
1. **具体性**: 抽象的なアドバイスではなく、具体的な手順やステップが示されているか
2. **実行可能性**: 提案がユーザーの状況（手持ちの材料、時間制約、スキルレベルなど）において実際に実行可能か
3. **明確な順序・優先度**: 複数のステップがある場合、実行順序や優先度が明確に示されているか
4. **時間・量などの数値情報**: 必要に応じて具体的な時間、量、温度などの数値が提供されているか
5. **リソースの考慮**: ユーザーが持っているリソース（道具、材料、時間）を考慮した提案になっているか
6. **代替案の提示**: 主要な提案がうまくいかない場合の代替案が示されているか

## 評価ルーブリック

| スコア | 定義 |
|--------|------|
| 5 | すべての提案が具体的で、ユーザーの状況を完全に考慮した実行可能なものである。明確な手順、数値情報、優先度が示され、代替案も適切に提供されている。ユーザーはこの回答だけで即座に行動に移せる。 |
| 4 | 提案は概ね具体的で実行可能。手順や数値情報も提供されているが、一部の詳細が不足している、または代替案が限定的。ほぼそのまま実行に移せるレベル。 |
| 3 | 基本的な方向性は正しいが、具体性が不足している箇所がある。一部の提案は追加の調査や確認が必要。実行するにはユーザー側での補完が必要。 |
| 2 | 抽象的なアドバイスが多く、具体的な手順が不明確。ユーザーの状況への考慮が不十分で、そのままでは実行が難しい。 |
| 1 | 提案が非現実的、または抽象的すぎて実行不可能。ユーザーの状況を無視した一般論に終始している。 |

## 出力形式

以下のJSON形式で出力してください：

```json
{
  "score": <1-5の整数>,
  "reasoning": "<評価の根拠を具体的な対話箇所を引用しながら説明（200-400字）>",
  "strengths": ["<良かった点1>", "<良かった点2>"],
  "improvements": ["<改善点1>", "<改善点2>"]
}
```

## 注意事項
- シナリオに記載されたユーザーの状況（時間制約、手持ちのリソースなど）を考慮して評価してください
- 「実行可能」とは、そのユーザーの具体的な状況において実行可能かどうかを意味します
- 具体的な対話箇所を引用して評価根拠を示してください
- 厳格に評価し、完璧でない限り5点は付けないでください
